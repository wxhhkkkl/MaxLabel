# 原生打印协议验证

## 自动验证

运行：

```powershell
npm run typecheck
npm run test:print
npm run fixtures:print
```

`fixtures/protocol` 会生成 80×60 mm、203 dpi 的 TSPL、ZPL、CPCL `.prn` 文件。样例覆盖文本、90° 旋转、Code 128、QR Code、Data Matrix、PDF417、矩形和 1-bit 图片。

## 实机步骤

1. 先确认打印机语言与样例一致，标签宽高为 80×60 mm，间隙纸，203 dpi。
2. 只向明确选中的标签打印机发送对应 `.prn`；不要向普通 A4 打印机发送原始指令。
3. 首次仅打印一张，核对走纸方向、实际尺寸、条码扫描、二维码纠错与图片黑白极性。
4. 分别再测 `copy=3`、90°/180°/270°、中文位图、边界对象、连续纸/黑标纸。
5. 记录品牌、型号、固件、连接方式、DPI、耗材尺寸和每项结果。固件方言差异必须按机型维护兼容配置，不能用一个型号的通过结果代表整个协议。

## 当前限制

- 原生指令与驱动打印共用页面拼版几何，可在同一物理页面内输出多行多列标签；仍需按具体卷纸宽度实机校准间距和偏移。
- CPCL 坐标会话按规范固定为 200 units/inch。300/600 dpi 机型需要实机校准。
- RFID 命令依赖具体打印机、标签芯片与固件，必须单独验证，测试时避免永久锁定。
- TSPL、CPCL 的非 ASCII 字体统一走预渲染 1-bit 位图，避免依赖打印机内置中文字库。
- 对于原生指令不能保持视觉一致的旋转、填充、颜色、复杂文字样式、椭圆和未知条码，客户端会整页预渲染为 1-bit 位图；若预渲染失败则阻止发送，不再静默跳过对象。

## 本机验证记录（2026-09-09）

本机只发现 Microsoft Print to PDF、OneNote，以及一台离线 HP LaserJet Pro M329；未发现串口或在线标签打印机。因此本轮完成了指令结构、字节边界、构建与样例文件验证，没有把普通打印机结果作为标签机实测结果。接入设备后按上面的实机步骤补录机型级结果。
