# Feature Specification: 真图层（图层管理）

**Feature Branch**: `019-layer-management`

**Created**: 2026-11-01

**Status**: Draft

**Input**: User description: "实现桌面端「真图层」功能：文档模型支持图层实体（新建/复制/删除/重命名/图层属性），图层面板工具栏不再置灰；对象可归属到图层，切换/隐藏/锁定图层时作用于其下全部对象；对象属性的「图层」下拉可把对象移到其他图层；图层面板关闭后可重新打开"

## 背景与问题

当前图层面板**只有对象列表**：可以选中对象、切换单个对象的显示/隐藏、上移/下移、删除，
但面板顶部的「新建图层 / 设置 / 复制图层 / 删除图层 / 重命名图层 / 图层属性」全部是
**硬编码禁用**，对象属性里的「图层」下拉也只有一个不可选的 `0`。

根因是**文档模型里没有图层实体**：对象只有 `visible` / `locked`，没有所属图层；
面板只是把对象（含分组子项）平铺成列表。因此「图层」的增删改没有任何可操作对象。

`docs/功能缺口清单.md` 第 283 条已把这列为已知缺口（标准级）：
「只有对象列表（选中/显隐/上下移/删除）；无图层实体与新建/删除/重命名/属性；
面板关闭后无法重新打开」。

本特性要补齐「真图层」，让图层成为可创建、可管理、可持久化的容器。

## Clarifications

### Session 2026-11-01

- **Q1 删除非空图层时，其下对象怎么处理？**（2026-11-01 所有者拍板）
  → **A：连同对象一起删除** —— 删除前必须明确提示「图层内有 N 个对象，将一并删除」，
  并且整次删除作为一步可撤销操作。
- **Q2 复制图层时，是否连同对象一起复制？**（2026-11-01 所有者拍板）
  → **A：连同对象一起复制** —— 副本中的每个对象都必须生成新的对象标识，不能与原对象冲突。
- **Q3 图层顺序是否决定跨图层的叠放顺序？**（2026-11-01 所有者拍板）
  → **A：是** —— 上层图层的对象整体显示在下层图层之上；渲染、打印预览与打印计划共用这一顺序。

- **Q4 当前活动图层被隐藏或锁定时，新建对象怎么处理？**（2026-11-01 所有者拍板）
  → **B：禁止新建并提示** —— 提示「请先显示或解锁当前图层」，不自动切换图层、也不改动图层的隐藏/锁定状态。

- **Q5 删除当前活动图层后，谁是新的活动图层？**（2026-11-01 所有者拍板）
  → **A：相邻图层** —— 优先原位置的上一个；没有则下一个；再没有则回到默认图层。

- **Q6 复制图层后，副本放在哪里、是否成为活动图层？**（2026-11-01 所有者拍板）
  → **A：副本放在原图层上方，并成为活动图层。**

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用图层组织对象 (Priority: P1)

操作员新建一个图层，把部分对象移入该图层；之后隐藏或锁定这个图层，画布上属于该图层的
对象一起隐藏或锁定，其他图层不受影响。

**Why this priority**：这是图层最核心的价值 —— 把「一组对象」当作整体控制。没有它，
图层只是空壳，后续的复制/删除/重命名都没有意义。

**Independent Test**：在一张有两个对象的标签上，新建「图层 2」并把其中一个对象移入，
隐藏「图层 2」后只有该对象消失，取消隐藏后恢复；锁定后该对象不能再被拖动。

**Acceptance Scenarios**：

1. **Given** 空白或已有对象的标签，**When** 新建图层，**Then** 图层面板出现新图层并成为当前活动图层。
2. **Given** 对象属于「默认」图层，**When** 在对象属性里把「图层」改为「图层 2」，**Then** 该对象从默认图层消失并出现在图层 2 下。
3. **Given** 图层 2 有 3 个对象，**When** 点击图层 2 的可见性开关，**Then** 画布上这 3 个对象一起隐藏；再点一次全部恢复。
4. **Given** 图层 2 已锁定，**When** 在画布上尝试拖动其中的对象，**Then** 对象不能被移动或编辑；其他图层的对象不受影响。
5. **Given** 图层 2 是活动图层，**When** 在画布上新建一个文字对象，**Then** 该对象自动归属图层 2。

---

### User Story 2 - 图层面板工具栏与面板重开 (Priority: P1)

操作员使用图层面板顶部的按钮完成新建、复制、删除、重命名、查看图层属性；面板被关闭后
还能从菜单重新打开。

**Why this priority**：用户明确要求「工具栏不再置灰」。这些按钮是图层管理的入口，
不实现就无法完成日常操作。

**Independent Test**：逐个点击工具栏按钮，确认每个按钮都有对应行为；关闭面板后通过菜单重新打开。

**Acceptance Scenarios**：

1. **Given** 图层面板，**When** 点击「新建图层」，**Then** 新图层被创建并选中。
2. **Given** 选中一个图层，**When** 点击「重命名图层」，**Then** 可以输入新名称，确认后面板与对象属性下拉即时更新。
3. **Given** 选中一个图层，**When** 点击「图层属性」，**Then** 打开属性对话框，可修改名称、可见性、锁定状态。
4. **Given** 图层 2 有对象，**When** 点击「复制图层」，**Then** 按 Q2 的结论产生新图层。
5. **Given** 选中图层 2，**When** 点击「删除图层」，**Then** 按 Q1 的结论处理其下对象。
6. **Given** 图层面板被关闭，**When** 打开「查看」菜单并选择「显示图层窗体」，**Then** 面板重新出现。

---

### User Story 3 - 图层随模板保存与打印 (Priority: P2)

操作员保存模板后重新打开，图层结构、对象归属、图层的可见/锁定状态保持不变；
打印时隐藏图层不输出、锁定图层正常输出。

**Why this priority**：图层如果不能持久化，每次打开都丢失，前面的管理动作就白做了；
打印是最终产出，必须与图层可见性一致。

**Independent Test**：新建两个图层并分别放入对象，保存、关闭、重新打开模板，核对图层与归属；
隐藏一个图层后打印预览，确认该图层对象未出现。

**Acceptance Scenarios**：

1. **Given** 含两个图层的模板，**When** 保存后重新打开，**Then** 图层名称、顺序、可见/锁定状态与对象归属全部保留。
2. **Given** 一个没有图层信息的旧模板，**When** 打开，**Then** 所有对象归入默认图层，且显示状态不变。
3. **Given** 某图层已隐藏，**When** 执行打印或打印预览，**Then** 该图层对象不输出。
4. **Given** 某图层已锁定，**When** 执行打印，**Then** 该图层对象正常输出。

---

### Edge Cases

- **删除默认图层**：默认图层 MUST 始终存在，不允许删除。
- **删除非空图层**：连同其下对象一起删除；操作前必须提示对象数量，且整次删除可一步撤销。
- **重命名成同名图层**：允许同名（内部按唯一标识区分），但界面应提示「已存在同名图层」。
- **隐藏当前选中对象所在的图层**：选中状态保留，但对象不可见、不参与打印；取消隐藏后恢复可见。
- **锁定图层中的对象**：不可选中、不可编辑，但仍可打印；对象属性里的锁定字段与图层锁定叠加生效。
- **空图层**：对象全部移走或删除后，图层本身保留，不自动删除。
- **删除当前活动图层**：删除后按「上一个 → 下一个 → 默认图层」切换活动图层，新建对象不会没有归属。
- **分组与图层**：分组整体属于一个图层；移动分组时组内对象一起移动，不允许组内对象跨图层。
- **活动图层被隐藏 / 锁定时新建对象**：不允许新建，提示先显示或解锁；不改动图层的隐藏/锁定状态。
- **复制图层**：连同对象一起复制；副本中的每个对象必须生成新的对象标识，不能与原对象冲突。
- **旧模板 / 导入文件没有图层信息**：一律归入默认图层，不丢对象。
- **撤销/重做**：图层的增删改、对象换层都 MUST 参与撤销/重做，一次操作一步。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 文档 MUST 支持图层实体，每个图层至少有唯一标识、名称、可见性、锁定状态与顺序。
- **FR-002**: 每个对象 MUST 归属且仅归属一个图层；新建对象 MUST 进入当前活动图层；若当前活动图层被隐藏或锁定，MUST NOT 新建对象，并提示先显示或解锁（Q4=B）。
- **FR-003**: 图层面板 MUST 以「图层 → 对象（含分组子项）」的树形结构展示，而不是当前的平铺对象列表。
- **FR-004**: 用户 MUST 能新建图层；新图层创建后 MUST 成为活动图层。
- **FR-005**: 用户 MUST 能重命名图层；改名后 MUST 立即反映到图层面板与对象属性的图层下拉。
- **FR-006**: 用户 MUST 能删除图层；删除非空图层时 MUST 连同其下对象一起删除（Q1=A），操作前 MUST 明确提示对象数量，且整次删除 MUST 可一步撤销。
- **FR-007**: 用户 MUST 能复制图层；复制 MUST 连同其下对象一起完成，并为副本中的每个对象生成新的唯一标识（Q2=A）；副本 MUST 放在原图层上方并成为活动图层（Q6=A）。
- **FR-008**: 「图层属性」MUST 提供名称、可见性、锁定状态三项编辑（本期不扩展其它属性）。
- **FR-009**: 切换图层可见性 MUST 同时作用于其下全部对象（画布、图层面板与打印）。
- **FR-010**: 切换图层锁定 MUST 同时作用于其下全部对象（不可选中/移动/编辑），但 MUST NOT 影响打印。
- **FR-011**: 图层顺序 MUST 决定跨图层的叠放顺序：上层图层的对象整体显示在下层图层之上；画布、打印预览与打印计划 MUST 使用同一顺序（Q3=A）。
- **FR-012**: 对象属性的「图层」下拉 MUST 列出全部图层，并允许把当前对象移动到其它图层。
- **FR-013**: 移动分组到其它图层时 MUST 整组移动，组内对象 MUST NOT 单独处于不同图层。
- **FR-014**: 当前活动图层 MUST 在图层面板中高亮；同一时刻只有一个活动图层；删除当前活动图层后 MUST 按「上一个 → 下一个 → 默认图层」的顺序切换（Q5=A）。
- **FR-015**: 图层面板关闭后 MUST 能通过「查看」菜单的「显示图层窗体」重新打开。
- **FR-016**: 图层结构、顺序、可见/锁定状态与对象归属 MUST 随模板保存与打开完整保留。
- **FR-017**: 打开没有图层信息的旧模板时，全部对象 MUST 归入默认图层，显示状态 MUST NOT 改变。
- **FR-018**: 从外部文件导入时 MUST 兼容无图层信息的数据：`.lsdx` 导入 MUST 归入默认图层；`.msdx` 的导入与导出 MUST 完整保留图层结构（本仓库没有 `.lsdx` 导出路径）。
- **FR-019**: 打印计划 MUST 排除隐藏图层中的对象；锁定图层中的对象 MUST 正常进入打印计划。
- **FR-020**: 图层操作与对象换层 MUST 进入撤销/重做历史；一次操作对应一步撤销。
- **FR-021**: 删除对象后空图层 MUST 保留；默认图层 MUST NOT 被删除，且 MUST 始终位于图层列表首位（最底层）。
- **FR-022**: 重名图层 MUST 被允许（按唯一标识区分），但保存/重命名时应提示同名。

### Key Entities *(include if feature involves data)*

- **图层**：文档内的容器；含唯一标识、名称、顺序、可见性、锁定状态；默认图层始终存在且位于最底层。
- **图层归属**：每个对象（分组视为一个对象）指向一个图层；用于面板树形展示、显隐/锁定传播与打印过滤。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在空白标签上新建图层并移动一个对象，操作在 30 秒内完成，且无需查阅帮助。
- **SC-002**: 隐藏一个图层后，画布与打印预览中属于该图层的对象数量为 0；其他图层对象数量不变。
- **SC-003**: 含 5 个图层、每层 20 个对象的模板，保存后重新打开，图层结构与对象归属的保留率为 100%。
- **SC-004**: 打开旧模板（无图层信息）后，对象总数与可见状态与打开前一致（0 丢失、0 误隐藏）。
- **SC-005**: 一次图层操作（新建/删除/重命名/移动对象/显隐/锁定）在撤销一次后完全回到操作前状态，成功率 100%。
- **SC-006**: 图层面板工具栏的 6 个按钮全部可用，0 个处于禁用状态。

## Assumptions

- 图层是**顶层容器**，与分组（group）并存：分组属于某个图层，但分组内部不再分层。
- 默认图层始终存在，可重命名，但不可删除；新建文档至少有一个默认图层。
- 图层属性本期只包含名称、可见、锁定三项；图层颜色、是否打印等扩展字段不在本期范围。
- 打印、导出与撤销沿用现有机制，图层只提供「哪些对象参与」的过滤与归属信息。
- 旧模板、旧导入文件没有图层信息时按「默认图层」处理，并在计划阶段明确迁移策略。
- 图层数量按数十个量级设计，不要求虚拟滚动等极端性能优化。
