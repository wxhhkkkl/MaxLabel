# 手工验证清单（019 真图层）

> 用最短路径证明 SC-001 ~ SC-006。自动化命令只跑单元 / 契约 / 集成；e2e 与真实画布交互
> 按下面手工步骤验证。

---

## 0. 前置

```bash
cd app
npm run typecheck          # node + web
npm run test:unit          # 单元测试（layers / 迁移 / 命令）
npm run test:contracts     # msdx 往返
npm run test:integration   # 面板/命令接线
```

> e2e 较慢（约 5.5 分钟），不要每次小改都跑；攒一批再执行（沿用仓库既有节奏）。

---

## 1. 图层容器与对象归属（SC-001 / SC-002）

| # | 操作 | 预期 |
|---|---|---|
| 1.1 | 打开一个空白标签，点击「新建图层」 | 面板出现「图层 2」并高亮为活动图层 |
| 1.2 | 在画布新建一个文字对象 | 该对象出现在「图层 2」下，而不是「默认」 |
| 1.3 | 在对象属性里把「图层」从「图层 2」改为「默认」 | 对象从图层 2 下移到默认图层下；画布不变 |
| 1.4 | 点击图层 2 的可见性图标 | 只有图层 2 的对象隐藏；默认层对象仍在 |
| 1.5 | 再点一次 | 图层 2 的对象恢复显示 |
| 1.6 | 锁定图层 2 后拖动画布中的对象 | 对象不可拖动；默认层对象仍可拖动 |
| 1.7 | 活动图层为隐藏/锁定时新建对象 | 提示「请先显示或解锁当前图层」，不创建对象 |

## 2. 工具栏与面板重开（SC-006）

| # | 操作 | 预期 |
|---|---|---|
| 2.1 | 逐个点击工具栏 6 个按钮 | 全部可点，分别打开新建/设置/复制/删除/重命名/属性 |
| 2.2 | 重命名图层 2 为「标签底图」 | 面板与对象属性下拉同步改为「标签底图」 |
| 2.3 | 复制「标签底图」 | 副本出现在原层上方，成为活动图层；对象为副本（改副本不影响原层） |
| 2.4 | 删除一个含 3 个对象的图层 | 先提示「图层内有 3 个对象，将一并删除」；确认后对象消失 |
| 2.5 | 撤销一次 | 图层与 3 个对象整体恢复 |
| 2.6 | 点击面板右上角 × 关闭面板 | 面板消失 |
| 2.7 | 「查看」菜单 → 勾选「显示图层窗体」 | 面板重新出现 |

## 3. 图层顺序与叠放（Q3）

| # | 操作 | 预期 |
|---|---|---|
| 3.1 | 两个图层各有互相重叠的对象，把上层图层下移 | 画布叠放顺序随之变化 |
| 3.2 | 打印预览 | 预览顺序与画布一致 |

## 4. 保存 / 打开与旧模板（SC-003 / SC-004）

| # | 操作 | 预期 |
|---|---|---|
| 4.1 | 建 2 个图层、分别放对象，保存 msdx 后关闭并重新打开 | 图层名称、顺序、可见/锁定与对象归属全部保留 |
| 4.2 | 用旧版本（v2）保存的模板打开 | 所有对象归入「默认」图层，显示状态不变 |
| 4.3 | 打开一个 v3 模板后再用旧版本客户端打开 | 旧客户端提示「模板文件版本不受支持」，不静默丢图层 |

## 5. 打印过滤（SC-002）

| # | 操作 | 预期 |
|---|---|---|
| 5.1 | 隐藏一个图层后打开打印预览 | 该层对象不出现 |
| 5.2 | 锁定一个图层后打印 | 该层对象正常输出 |
| 5.3 | 对象自身隐藏 + 图层可见 | 该对象仍不输出 |

## 6. 撤销 / 重做（SC-005）

| # | 操作 | 预期 |
|---|---|---|
| 6.1 | 依次执行：新建图层 → 移对象 → 隐藏 → 锁定 → 复制 → 删除 | 每一步撤销一次回到上一步；重做可逐步恢复 |
| 6.2 | 连续重命名同一图层（快速输入） | 合并为一步撤销（沿用 `applyDocument` 的 coalesce 规则） |

## 7. 显式不自动化

- 数十图层 / 数百对象下的交互流畅度：以手工体验为准（本期不引入性能基准）。
- 真实打印机输出与图层可见性的一致性：沿用既有打印链路，按 5.1~5.3 的预览结果抽检。
