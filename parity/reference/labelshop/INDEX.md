- **驱动工装**：`tools\parity\LabelShopCtl.ps1`（未做任何修改）、`tools\parity\Crop-Image.ps1`

**采集限制（本机环境）**
1. **原版画布与 MFC 工具栏不响应合成输入**：150% DPI 缩放（物理 2560x1600 / 工装侧虚拟 1707x1067）导致 `click:`/`clickdlg:` 落点差 1.5 倍；改用 `_click.ps1`（unaware 上下文自算坐标 + 自带 SetCursorPos，`GetCursorPos` 回读证明落点精确）后鼠标仍不被接受。父代理新增的 `postclick:`/`postdbl:`（窗口消息投递到框架窗口/文档视图，客户端坐标）同样**不产生任何效果**——这已排除"坐标算错"这一解释，剩下的是原版视图对消息的处理方式（可能要求真实输入队列/焦点/`WM_MOUSEACTIVATE` 流程）。**可用的可靠通道只有：`Ctrl+N`/`Ctrl+P` 等快捷键、对话框上的 `Alt+<字母>`、以及父代理新增的 `btn:`（`BM_CLICK`）**——`btn:` 已成功唤起过 `高级打印选项`。
2. **高于桌面的对话框**：工装侧虚拟屏高仅 1067，原版部分对话框初始位置靠下、底部按钮会落到屏幕外。用 `_dp.ps1` 重定位到屏内即可完整抓取（`61-dlg-custom-label.png` 即此法所得）。注意 `shotdlg` 取的是**面积最大**的可见对话框而非最上层，多对话框叠加时会抓错（需先用 `_dp.ps1` 把目标放大到超过其它对话框，或直接从桌面截图按已知矩形裁剪——`64a/64b` 用的就是后者）。
3. **MFC 弹出菜单不吃键盘**：`Alt+F` 能打开文件菜单弹窗，但菜单打开后 `keys:{DOWN}`/`keys:{ENTER}`/`keys:<字母>` 与 `keys:{ESC}` 全部无效（菜单会一直停在屏幕上，需用 `_fgkeys.ps1` 发 ESC + 点击别处才能收起）。因此**菜单项无法用键盘选择**，只能靠 `shotpopup` 取证文字。
4. **`listctl:` 只枚举直接子控件**（非递归，尽管注释写"递归"），且根窗口取「面积最大的对话框」而非最上层——枚举嵌套对话框（如 `高级打印选项` 内嵌 `#32770 页眉页脚`）时需改用 `_enum.ps1`（按标题精确定位 + `EnumChildWindows` 全后代）。
5. 采集过程中真机进程曾三次因打印相关 Shell 模态（`btn:高级选项` 触发的嵌套模态）**导致工装调用超时/失去键盘响应**，通过重启 `LabelShop.exe` 进程恢复；未卸载、未改动任何产品文件。
