# 更正（验收方 round-79）：真机「条码」页**有**颜色控件 —— round-113 的"定案"是误判

## 一、结论（一句话）

真机「条码属性 → 条码」页**页尾有 `颜色:` 控件**（黑色色块 + 下拉箭头）。
round-113 依据**文本 dump** 判定"该页没有颜色控件"、并把复刻版的「条码颜色」**迁到了「常规」页** —— **这个处置是错的，应当改回**。

## 二、证据

| 证据 | 内容 |
| --- | --- |
| `parity/reference/labelshop/verifier-20c-barcode-page.png`（779×818，真机实拍） | 「条码」页自 上而下：`条码符号类型(码制)(B):` → 尺寸组（`X 尺寸(X):` / `码  高(H):`）→ `条码特殊选项` 组（`☐GS1/EAN 128(U)` / `字符集(C):`）→ `供人识读字符` 组（`位置(P):` / `垂直偏移(O):` / `对齐方式(A):` / `☐字符模板(T)`）→ **`颜色:` + 黑色色块 + 下拉** → 底排 `确定/取消/帮助` |
| `parity/review/cmp-props-r113.png`（本轮新出的并排图） | 左（真机）**能看到颜色行**，右（复刻版 round-113）该行**已不在条码页**（被迁到常规页）——并排图一眼就暴露了这个错 |

## 三、为什么 round-113 会判错（根因）

它用的是**控件树文本 dump**（`probe-45-barcode-props-p3.txt`），而真机的颜色控件是**owner-drawn 的色块 + 一个很小的下拉箭头**，
不是标准 `ComboBox`/`Static`，**树枚举不到它** → 该页在 dump 里只剩 8 行，"颜色"整行消失。
→ 教训：**图片证据优先于文本 dump**；dump 里"少一行"时，先怀疑 dump 能力，不要直接判定"原版没有"。

## 四、正确的目标状态

| 位置 | 真机 | 复刻版应有 |
| --- | --- | --- |
| 「条码」页 页尾 | `颜色:` + 色块 + 下拉（色块显示当前颜色） | 恢复 `条码颜色`（testid `barcode-color` 不变即可），放回**条码页页尾**、在「供人识读字符」组之后 |
| 「常规」页 | `颜色(&C):` 下拉，本机值 `固定颜色`（这是**颜色模式**，与上面的色块不是同一个东西） | 若复刻版常规页原本就有颜色模式项，**保留**（不要因为它"也叫颜色"就把条码页那条删掉） |
