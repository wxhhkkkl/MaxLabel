# 子任务规格：从 LabelShop 中文帮助提取 parity 表行

## 输入
已抽取的纯文本帮助文档位于 `D:\workspace\maxlabel\parity\_extract\<basename>.txt`（UTF-8）。
每份文件的第 1 行形如：`=== menu_file.html === TITLE: 文件菜单`。
正文由该 html 的 `#winchm_template_content` 区域抽取，`|` 表示原 html 表格的单元格分隔。
原文为简体中文，术语按原文保留（如"签赋LabelShop"、"数据源"、"模板"、"属性页"）。

## 输出
写入指定文件（UTF-8，无 BOM），**只包含数据行**，不含表头、不含 markdown 表格分隔行、不含章节标题。
每行格式（7 个字段，用 `|` 分隔，行首行尾各有一个 `|`）：

```
| <功能点> | <原版行为要点> | <出处文件> | 待核 |  |
```

即：第 1 列留空（由主控填编号），第 2 列功能点，第 3 列原版行为要点，第 4 列出处文件，第 5 列固定 `待核`，第 6 列证据留空。
示例（仅示意格式，内容不要照抄）：
```
| 文件菜单 → 另存为，保留原文件并另存为新名称 | 菜单项"另存为"；说明为"换名保存当前编辑的标签模板文档"；快捷键 Alt+F 调出文件菜单 | menu_file.html | 待核 |  |
```

## 硬性要求
1. **禁止编造**。每条的功能点与要点必须能在对应抽取文本中找到依据。文档没写的默认值/快捷键/范围就不要写。
2. **功能点必须原子化、可执行、可见**：写"用户能点到/看到的具体操作或元素"，例如"格式栏 → 字号下拉框，输入 1–999 pt"；禁止"支持打印""支持条码"这类笼统条目。
3. **原版行为要点**里，凡帮助文档写明的**默认值、快捷键、取值范围、单位、选项枚举、顺序、错误处理、交互流程**必须写进去；用分号分隔。取值示例：`默认"自动"字符集`、`范围 1–31`、`单位 mm`、`快捷键 Ctrl+Shift+...`。
4. **出处文件**列填**原 html 文件名**（不是 txt 名），多个用半角逗号+空格分隔，如 `menu_file.html, label_label_saveas.html`。
5. **覆盖度**：分配给你的每个 html 文件都必须至少出现在一行里；重点文件按分配说明产出多条。
6. **纯文本**：功能点与要点里不允许出现任何 HTML 标签或实体残留（`<p>`、`<br>`、`<BR>`、`&nbsp;`、`<FONT`、`</div>`、`&amp;` 等）。原文中的 `<HT>`、`<SOH>` 这类**控制字符表示法**是文档正文内容，可以保留。
7. 不要在功能点/要点里放图片链接、URL、`Image/xxx.png`、`[图]` 之类引用。
8. 功能点列不要用换行；整行必须是一行。功能点内如需分段用 `；`。
9. 功能点/要点里不要出现未转义的 `|` 字符。若原文含竖线，改写为 `/` 或中文"或"。
10. 不要写"原版"以外的主观评价，不要写"复刻状态"以外的结论。

## 自检（必须做）
写完后用 grep/read 自检：
- 行数统计；
- `Select-String -Pattern '<[a-zA-Z/]' ` 检查 HTML 残留；
- `&nbsp;`、`&amp;` 残留；
- 是否每个分配文件都出现在出处列。
